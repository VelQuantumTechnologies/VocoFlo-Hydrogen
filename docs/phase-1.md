# Phase 1: one usable coaching experience

## Deliverable

A working path from free speaking check-in to P01, one responsive roleplay, saved observation/transfer plan and a subsequent personalised opening. Include real Gemini analysis once the founder's tested configuration is supplied. Build a single meaningful visual for P01; full-catalogue animation is later work.

## Scope

1. Audio setup and user-started recording, reading alternative and interruption recovery.
2. Short check-in with goal/context, speech samples, optional self-report, actual analysis and useful debrief.
3. P01 with an early micro-attempt, authored teaching, metaphor visual, one experiment and prepared rehearsal.
4. A separate genuinely responsive scenario roleplay with a distinguishable partner presentation/voice.
5. Communication-first review, optional event inspection with corrections and a saved transfer step.
6. Cross-session memory grounded in what the learner shared; editable/deletable.
7. Local/static repeat practice without paid analysis, plus usage logging for live operations.
8. Development entitlement/paid invitation preview; production payment setup waits for approved commercial terms.

Hydrogen chooses the concrete platform, architecture and milestones. Keep the first version easy for Chetan to run on a real device. Do not build a separate validation programme before integrating the analysis.

## Acceptance checks

| Check | Observable result |
| --- | --- |
| Audio-first | Coco narration works; pause/replay and reading controls are accessible |
| Recording | User starts/stops the microphone; Coco output is not captured as learner speech |
| Clean speaking state | No grading, event alerts or reminder banners during speech |
| Experience-first | Learner can speak/respond early without listening to six teaching blocks |
| Grounded teaching | P01 meaning and source text remain available; visual explains the concept |
| Question return | Asking Coco returns to the correct lesson step without resetting the attempt |
| Live roleplay | A relevant answer changes the partner's next reply; fixed prompts are labelled separately |
| Actual analysis | Real configured request yields timed moments; no fixture is passed off as real |
| Correction | Dismissed/corrected event remains corrected after reopening history |
| Covert effort | Fluent-sounding sample can coexist with reported difficulty; self-report can be skipped |
| Review | Message and experience lead; timeline remains optional |
| Memory | Next opening uses a genuine saved report/plan; deletion prevents later reuse |
| Static practice | Repeated practice runs without a paid analysis call |
| Failure | Denied mic, timeout or malformed analysis leaves a usable retry/continuation |
| Resume | Backgrounding or returning does not restart an unintended recording/upload |
| Usage | Actual live calls, retries and unknown costs are distinguishable |
| Entitlements | Development access cannot be mistaken for a real sale or lifetime live AI |

Use focused automated checks for contracts, corrections, state progression and request deduplication, plus a real device walkthrough for audio/recording. Report unavailable checks honestly.

## After the first build

Chetan tests the experience and detector inside the app. Fix concrete issues, review actual cost/latency, then scale delivery across the existing content. Body-tool demonstrations need authored models that match the physical teaching notes; do not substitute invented mechanics or claim missing demonstration assets exist.
